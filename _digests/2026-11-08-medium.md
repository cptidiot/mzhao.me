**Medium 精选（2026-11-08）**

- [Spec-Driven Development — Spec Rework Rate and Cost per Accepted Change Instead of AI Agent Speed](https://medium.com/@wasowski.jarek/spec-driven-development-spec-rework-rate-and-cost-per-accepted-change-instead-of-ai-agent-speed-43e4718a1d86)：衡量 AI 智能体别看提速百分比，要看每次被接受变更的成本和需求返工率。最严谨的生产力研究自相矛盾：同一团队先测出用 AI 反而慢 19%，后续又称某组快 18%，作者自己都说新数据不可靠。速度在实验室里都难可靠度量，冲刺报告的提速数字同样有入样偏差却无人记录。作者建议改用“每次被接受变更的成本”与“需求返工率”，并给出在 Jira 或 Git 里直接数数的规则和一份度量日志模板。会员专享，文本抓取仅读到开头。
- [Claude Code agents: what they actually are](https://medium.com/@joparga3/claude-code-agents-what-they-actually-are-2d6ea121b936)：Claude Code 的 subagent 不是“更聪明的提示词”，而是跑在独立上下文窗口里的独立执行体。作者第一次看 Claude 派生 subagent 处理十几个文件并返回干净总结时，以为只是换了个更好的提示词。实际区别在于：agent 不在主对话里运行，而是有自己的上下文窗口、系统提示、工具权限，独立工作后再返回结果。文章从零讲清这一机制：agent 到底是什么、怎么建、什么时候值得投入，面向已在用 Claude Code、想先把功能理解透再动手的人。会员专享，文本抓取仅读到开头部分。
- [DataJunction as Netflix's answer to the missing piece of the modern data stack](https://medium.com/@netflixtechblog/datajunction-as-netflixs-answer-to-the-missing-piece-of-the-modern-data-stack-92af926b40a5)：Netflix 用开源语义层 DataJunction 统一指标定义，让实验指标从数周上线变成集中管理、处处一致。Netflix 的指标曾散落在各处、定义不一、难以发现和信任，实验平台受影响最大：上线一个新指标要数周，还要懂业务知识与实验约定。DataJunction 是开源的指标/语义层，把指标与维度定义存在一张连通图里，用 SQL 解析与生成引擎对外服务，分析立方体（cube）作为消费接口，可物化到 Druid。Netflix 在内部 Mando、Airbnb 的 Minerva 与 DJ 之间选了 DJ，胜在 SQL 引擎扎实且是当时唯一用图存定义的开源方案。浏览器复核已读全文。
