      **核心论点**

      - 2025 年是 LLM 进展强劲、多事的一年。Karpathy 列出六个令他印象最深的"范式转变"（paradigm changes）——在概念上改变格局的变化，而非单纯的能力榜单。
      - 总判断：LLM 是一种新型智能，比他预期的更聪明、也更愚蠢；极其有用，但行业连其现有能力的 10% 都远未兑现；同时他相信会继续快速进步，也还有大量工作要做。

      **1. RLVR：训练流程新增一环**

      - 生产级 LLM 训练配方新增第四段：在预训练、SFT、RLHF 之后，RLVR（基于可验证奖励的强化学习）用数学、代码等可自动验证的奖励训练，模型自发学会"推理"——拆解问题、来回试错；这些策略很难靠人工写出最优推理轨迹来教，只能靠奖励优化让模型自己找到。
      - RLVR 的 capability/$ 很高，吞掉了原定用于预训练的算力：2025 年大部分能力进步来自把这一新阶段的"存量红利"吃掉，模型尺寸相近、RL 跑得更久。还带来一个全新旋钮和对应的 scaling law：拉长推理轨迹、增加"思考时间"来换取能力。OpenAI o1（2024 年末）是首次展示，o3（2025 年初）是能直观感受到差别的拐点。

      **2. Ghosts vs Animals：锯齿状智能**

      - 我们不是在"培育/生长动物"，而是在"召唤幽灵"（summoning ghosts）：神经架构、训练数据、训练算法、优化压力全都不同，产物自然是智能空间里很不一样的实体，不宜用动物视角去理解。
      - 人类神经网络为"丛林部落生存"优化，LLM 则为"模仿人类文本、在数学题里拿奖励、在 LM Arena 上拿人类点赞"优化，于是能力在可验证领域附近"尖峰突起"，整体呈现滑稽的锯齿状：同一时刻既是天才博学家，又是会被 jailbreak 骗去泄露数据的、认知有困难的小学生。
      - 他也因此对 benchmark 普遍失去信任：benchmark 几乎天然就是可验证环境，立刻会被 RLVR 及弱化版（合成数据）盯上；实验室的 benchmaxxing 流程就是在 benchmark 占据的 embedding 空间小块附近建环境、把"锯齿"长过去覆盖它，"在测试集上训练"已成一门艺术。问题是：刷爆所有 benchmark 却仍未达到 AGI，会是什么样子？（本节指向他的三篇旧文：Animals vs Ghosts、Verifiability、The Space of Minds。）

      **3. Cursor：LLM 应用新层**

      - Cursor 最值得注意的不只是今年的迅猛崛起，而是它令人信服地揭示了一个新的"LLM 应用"层——人们开始说"X 领域的 Cursor"。这类应用把 LLM 调用打包编排进特定垂直领域：做 context engineering；在底层把多个 LLM 调用串成越来越复杂的 DAG，精细权衡性能与成本；提供面向人机协同的应用专属 GUI；提供"自主程度滑杆"（autonomy slider）。
      - 2025 年争论最多的是这一层有多"厚"：LLM 实验室会吞掉所有应用，还是留有绿地？他个人猜测：实验室会倾向于培养出"普遍能干的大学生"，而 LLM 应用会通过提供私有数据、传感器与执行器（sensors and actuators）和反馈回路，把一群这样的"大学生"组织、微调并实际部署成特定领域的专业人士。

      **4. Claude Code：住在你电脑里的 AI**

      - Claude Code 是第一个令人信服的 LLM Agent 演示：以循环方式把工具使用和推理串起来，解决延展性问题。更重要的是它运行在你的电脑上、带着你的私有环境、数据与上下文。
      - 他认为 OpenAI 走错了路：早期 codex/agent 努力聚焦在云端容器部署、由 ChatGPT 编排，而不是简单的 localhost。云端 agent 群固然像是"AGI 终局"，但我们处在一个中间态、缓慢起飞（slow takeoff）、能力锯齿状的世界，直接在开发者电脑上跑 agent 更合理。关键区别不在"AI 算力"跑在哪里（云端、本地都无所谓），而在其余一切——已开机、已安装好的电脑、它的上下文、数据、密钥、配置和低延迟交互。
      - Anthropic 把这个优先级顺序搞对了，把 CC 打包成令人愉悦、极简的 CLI 形态，改变了 AI 的样子：它不再只是像 Google 那样"去访问的网站"，而是一个住在你电脑上的"小精灵/幽灵"（a little spirit/ghost）——一种全新、独特的人机交互范式。

      **5. Vibe coding**

      - 2025 年 AI 跨过了能力门槛：只需用英语就能构建各种令人印象深刻的程序，甚至忘了代码的存在。好笑的是，"vibe coding"这个词是他随口发推造出来的，完全没想到会传这么远。
      - 编程不再专属于高度训练的专业人士，任何人都能做。这又是他《Power to the people》一文的例证：与以往所有技术相反，普通人从 LLM 获益比专业人士、企业和政府更多。同时它也让专业人士写出大量"否则永远不会被写出来"的软件：他在 nanochat 里自己 vibe coded 一个 Rust 高效 BPE tokenizer，而不必采用现有库或把 Rust 学到那个水平；今年还 vibe coded 很多小项目作为想要存在的东西的快速演示（MenuGen、llm-council、reader3、HN time capsule），甚至为找一个 bug 而 vibe coded 一整个用完即弃的临时应用——代码突然变得免费、短暂、可塑、用完即弃。Vibe coding 将重塑软件形态并改变职位描述。

      **6. Nano banana / LLM GUI**

      - Google Gemini Nano banana 是 2025 年最令人难以置信、改变范式的模型之一。在他的世界观里，LLM 是下一个重大计算范式，类似 1970、80 年代的计算机；因此我们会看到类似原因驱动的类似创新：个人计算、微控制器（认知核心）、互联网（agent 之网）的等价物等等。
      - 特别是在 UI/UX 上：与 LLM"聊天"有点像 1980 年代对着计算机控制台发命令。文本是计算机（和 LLM）偏爱的数据表示，但不是人偏爱的格式——人其实不喜欢读文本，又慢又费力；人喜欢视觉化、空间化地消费信息，这正是传统计算发明 GUI 的原因。同样，LLM 也应该用人偏爱的格式跟我们说话：图像、信息图、幻灯片、白板、动画/视频、Web 应用等等。现阶段的早期版本是 emoji 和 Markdown——给文本"打扮"、排版以便阅读。但谁来真正建造 LLM GUI？Nano banana 是这可能长什么样的第一个早期信号；关键不只是图像生成本身，而是文本生成、图像生成与世界知识在模型权重里纠缠在一起的联合能力。

      **Takeaway**

      - 六个转变其实讲的是同一件事：LLM 不再只是"聊天框里的模型"，而是在变成一种新型智能、一种新应用层、一种住在你电脑里的 agent、一种人人可用的编程方式，以及一种视觉化的交互界面。
      - 值得跟进的是 RLVR 带来的推理能力、应用层的 context engineering 与自主滑杆、本地 agent 的私有上下文，以及用 vibe coding 把"想要存在的东西"快速做出来；同时保持清醒：能力锯齿状，同一模型既天才又幼稚，关键任务上别盲信。
